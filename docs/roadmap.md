# Nim 开发路线与架构约定

> 本文件同步了本项目的核心架构决策、产品语义与后续开发路线，作为仓库内的轻量参考，避免切换工具或新开会话后上下文丢失。

## 一、核心架构与产品约定

1. **模块划分与依赖方向**（由 `eslint.config.mjs` 的 `moduleTiers` 强制检查）
   - 顶层按能力划分为 `modules/auth`、`modules/markdown`、`modules/media`、`modules/posts`、`modules/site`。
   - `lib/` 与 `components/` 不认识具体业务；模块内 `server/` 仅在服务端运行，浏览器端只能通过 `server/actions/` 调用；同层模块互不引用。
   - 新增内容栏目时按 `modules/<能力>/` 建模块并登记到 `eslint.config.mjs`，跨内容功能（如站内搜索）放在内容模块之上的一层。

2. **设计语言与布局规范**
   - 公开页与管理后台属于同一网站，共享视觉体系与组件（shadcn + Motion），不另起一套后台风格。
   - 全站采用“铺满视口的页头/页脚 + 最宽 1200px 的 12 列画布 + 页面声明版式（概览 / 阅读 / 列表-详情 / 工作区 / 聚焦）”。
   - 断点按窗口尺寸等级设定（`sm` 600 / `md` 840 / `lg` 1200 / `xl` 1600）；颜色统一使用 `app/globals.css` 中的语义变量，由 ESLint 禁止在界面代码里直接写色板字面色。
   - 导航遵循唯一性规则：同一栏目任一时刻只在一处显示（桌面页头放精选栏目，其余与手机端全部栏目进左侧抽屉）。

3. **写作、修订与媒体边界**
   - 文章 ID 统一使用系统生成的 UUID，修改标题不改变文章地址；文件导入仅按元数据 `id` 决定覆盖目标草稿，不直接发布。
   - 本机（IndexedDB）持续保存写作恢复副本（含离线编辑与多标签隔离），服务端内容与修订历史只由保存、导入、恢复历史、发布等明确动作改变；每条修订保存完整快照，恢复只追加新修订。
   - 未发布图片仅管理员可读；发布时由 `remark-rehype` 解析实际引用的站内图片并登记到 `post_publication_media`。

4. **认证、存储与部署目标**
   - 首版采用 GitHub 单管理员登录（Better Auth + SQLite 会话，按 `ADMIN_GITHUB_ID` 授权），不开放公众注册、密码或 Passkey；认证入库保留 Better Auth 原生 SQLite 的多步事务保证，表结构统一由 Drizzle schema 与迁移管理。
   - 近期以单机 VPS 为部署目标：生产构建必须设置 `SITE_URL`，更新部署时保留数据库与自动生成会话密钥所在的持久化目录。

5. **当前阶段开发原则**
   - 开发期直接升级并同步更新所有调用方与测试，不为旧内部接口保留兼容双轨。
   - 保持细颗粒度本地提交（每类改动独立通过 `lint`、`check-types`、单元测试与必要 E2E），不擅自推送远端。

## 二、当前分支与进度

- `main`：基础版本。
- `feat/writing-recovery` / `refactor/modules`：写作恢复、渲染对照、图片上传及按能力模块化重构（已完成）。
- `feat/layout-and-tokens`（当前开发分支）：语义 CSS 变量、集中路由（`lib/routes.ts`）、全站外壳与导航、各页版式统一、文章目录与滚动高亮（已完成）。

## 三、后续开发路线

### P0：收口小问题与分支整理
- [x] **统一文章 ID 契约**：将草稿模型、导入与服务端动作收口为统一 UUID 校验（仅保留对底层既有损坏数据的防御边界）。
- [x] **收口 Server Action 重复包装**：抽取 `modules/posts/server/actions/` 共用的鉴权、控制流透传与错误兜底辅助函数。
- [ ] **本地分支合并收口**：确认无误后将历史功能分支有序整理回主干。

### P1：媒体能力与 Gallery 栏目
- [ ] **后台媒体管理与引用查询**：查看已上传图片资源及被文章发布引用的状态，支持清理/管理。
- [ ] **编辑器图片就地呈现**：当前编辑区图片仍显示 Markdown 语法文本，后续实现所见即所得的就地预览。
- [ ] **Gallery（相册 / 画廊）模块**：在媒体管理稳定后按 `modules/gallery/` 落地并接入导航清单。

### P2：站内搜索
- [ ] **跨内容站内搜索**：作为内容模块之上的一层接入；具体检索范围、交互形态、排序与中英文分词/引擎方案待专项讨论确定。

### P3：文档对齐与真机 / 真实环境验收
- [ ] **对齐公开文档**：更新 `README.md` 与 `INSTALLATION.md`，补全 SQLite 持久化、Drizzle 迁移、显式导入旧文、`SITE_URL`、VPS 部署及 GitHub OAuth 回调配置说明。
- [ ] **真实环境验收**：在真实域名与 GitHub OAuth App 下复测 Better Auth 登录授权；在真机环境下验收 Markdown 编辑器的输入法（IME）交互。
